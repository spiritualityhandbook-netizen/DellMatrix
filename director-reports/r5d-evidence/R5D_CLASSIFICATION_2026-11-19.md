## Classes (per R5D_PREP §2.2)

- A — note is the first/only mutation on the path: door refusal is
  pre-mutation by construction; no caller change needed.
- B — preflightable: caller mutates before noting, but the noted text is
  computable before the first mutation; the build inserts a history
  preflight (would-admit check) ahead of the first mutation and T5
  spot-proves refusal atomicity per class.
- C — HOLD (non-preflightable as written): the caller cannot admit-check
  before its mutations without redesign or per-path proof. These stay
  on HOLD in the R5-D build scope until individually discharged; the
  build authorization ask must name them as excluded or separately
  scoped — they are NOT silently bypassed.

## Counts: A=26  B=45  C-HOLD=39  DOOR=1  TOTAL=111

## Method + limits (honest)

AST pass (r5d_classify.py) per call site: enclosing function, mutating
statements before/after the call (attribute/subscript assigns + known
mutating method calls), control context (loop/try/conditional). LIMIT:
counts are FUNCTION-level, so dispatcher functions (execute_seed,
_execute_intent) accumulate mutations from sibling arms that never run
on a given path — that over-approximation is one reason those sites
are class C (per-arm path proof owed) rather than B. Class B is an
analyst judgment from the same evidence (single-purpose functions,
note text from call arguments); it is a build obligation to spot-prove
(T5), not a proof. Evidence rows: r5d_sites.jsonl.
