## 2. Transaction plan (design only — for Keeper challenge)

1. Canonical measurement: history-section byte cost measured on the actual
   atomic_write_json serialized payload contribution (parity-proven against a
   full-payload serialize in tests), never raw char count. Cap: 10,000 entries
   AND 2,097,152 canonical bytes, first-reached binds; exact-fit admitted.
2. Pre-mutation gate: sanitize (P5) -> measure -> admit/refuse BEFORE any
   owner-state mutation. Refusal is typed, carries requested/accepted/remaining
   + safe recovery hint, no raw sensitive text. Callers that mutate owner state
   before calling note/note_seed must preflight the append (staged append or
   proven rollback); any caller that cannot meet this stays on HOLD per P2 —
   the ~98 call sites are classified in the R5-D build into (a) note-last
   (append is final mutation), (b) preflightable, (c) HOLD until tested.
3. Save/restore: remove both cuts; save writes full history; restore loads
   full history. Legacy over-budget: load preserves all entries, owner marked
   LEGACY_OVER_BUDGET, unchanged-history write-through allowed, new growth
   refused LEGACY_OVER_BUDGET_NEW_ENTRY_REFUSED (P4). No eviction ever.
4. Aggregate (P3): report-only census job (owner/checkpoint counts + disk
   bytes, no owner IDs in receipts); warn >=512 MiB, critical >=1 GiB;
   unscannable roots = coverage UNKNOWN. No quota, no auto-delete.
5. Privacy (P5): ALL note/note_seed strings pass sanitize_text before
   retention/admission/echo/persist/replay; entries whose redaction changes
   replay semantics are marked NON-REPLAYABLE. Disclosed limits stand:
   keyword-free/multi-token secrets can miss; benign prose can be altered.
   No claim of complete secret protection.
6. history_report (P6): always shows shown/total; power-loss durability
   remains UNKNOWN (process tests = INTEGRATION evidence only).

## 3. Failing-first test plan (tests written FIRST in R5-D build; each must
##    FAIL on current main for the stated reason before any fix)

   (fails today: persist.py:378 keeps 24).
T2 restore-full: file with 30 entries incl. one 200-char entry -> load ->
   history == 30 entries, long entry byte-identical (fails today:
   persist_rest.py:643 cuts to 24 and 120 chars).
T3 exact-fit: history at exactly 10,000 entries / exactly 2,097,152 canonical
   bytes admitted; +1 entry or +1 byte -> typed refusal, state unchanged.
T4 refusal atomicity: at-cap note() and note_seed() refusals leave owner
   graph/selection/undo/ledger, history, durable generation SHA and
   checkpoint pointer byte-identical (preflight contract, P2).
T5 caller atomicity spot-set: representative callers from each census class
   (a)/(b) prove refusal leaves their own mutations unapplied; class (c)
   callers enumerated and held, not bypassed.
T6 canonical parity: history-section measurement == its byte contribution
   in the full atomic_write_json payload for ASCII, CJK and emoji corpora
   (escaping overhead included).
T7 legacy: >cap legacy file loads whole, marked LEGACY_OVER_BUDGET;
   unchanged-history save byte-preserves history; new note refused
   LEGACY_OVER_BUDGET_NEW_ENTRY_REFUSED pre-mutation.
T8 sanitize-at-capture: canary secret-shaped strings via ordinary note()
   and note_seed() appear on NO surface (history, saved JSON, reload,
   replay, macro_seed, history_lines) unsanitized; redaction-changed
   entries marked NON-REPLAYABLE; benign-string semantic-loss cases
   recorded honestly, not asserted away.
T9 aggregate report: synthetic multi-owner tree -> census counts/bytes
   correct, thresholds flag at 512 MiB / 1 GiB, no owner IDs in receipt,

T10 history_report truthfulness: shown/total correct at 0, 16, 10,000 entries.
T11 crash windows (INTEGRATION only): kill between temp-write/replace/
