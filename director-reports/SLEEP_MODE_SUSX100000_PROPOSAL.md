## Operating design (Uni's preparation, for Director comment)

1. **Reconciliation first.** Cycle 1 re-verifies every deferred
   item against current main and republishes the inventory with
   honest states (closed-by-later-work / open / gated). No item
   is worked — or claimed — from stale paper.
2. **Dependency-ordered circuits.** Each item (or coherent
   cluster) runs the full circuit discipline: ground
   (discover/verify/classify) → SWAT Director's-eye pre-mortem →
   failing-first where a defect is claimed → build → mutants →
   regression ×3 sequential → PR → exact-head CI → merge only
   under the hard terminal-green gate → per-circuit record.
3. **State discipline.** State-sharing campaigns sequential or
   isolated (§ standing rule); chain logs durable under the
   goal's hidden_files; truncated/interim output is never a
   result; identifiers only from terminal output.
4. **Pacing.** Hyperdrive: continuous cycles with zero idle
   time between circuits; a blocked item is parked with its
   blocker recorded and the next item begins immediately
   (never stall the queue on one gate).
5. **Research.** External research (papers, repos, issues,
   postmortems, community evidence) is used where an item's
   current issue benefits, with coverage notes kept per item —
   not repeated top-result searching.
6. **Morning report.** On "wake up" (or run conclusion): a
   Director-format report — completed items with evidence,
   partial items with exact remaining work, gated items with
   what they wait on, and every failure encountered with its
   classification. Full completion is the goal; the report
   claims only what the evidence carries.
7. **Safety rails unchanged.** Standing authorization scope,
   product security/authority boundaries, and the hard merge
   gate all bind the run exactly as they bind wake work.
