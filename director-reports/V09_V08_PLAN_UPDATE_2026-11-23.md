- Navigation itself changes no canonical idea state.

**Reads (authority/store):** no store reads of its own. Counts shown
in the rail come from the same single `_state_payload` canonical
snapshot each page already consumes; the shell introduces no second
payload and no client-side count derivation from truncated slices.

**Test-first contract (must be written failing-first):**
- Route/shell assertions: all five destinations reachable from the
  rail on every page; exactly one `aria-current` per page and it
  names the current view.
- Keyboard-only traversal of the full journey in order and in
  reverse; focus visible and never lost into hidden DOM on mobile

- Count honesty: with 21+ proposals, the rail Nursery badge (if any)
  shows the canonical total form (e.g. "20 of 21" semantics), never

## 3. SELECTION 2 — V09-TREE: CANONICAL IDEA-PARENTAGE TREEVIEW

**Decision (both dispositions agree):** a canonical, read-only
idea-parentage TreeView, colocated with Nursery's proposal lineage
and discoverable from Plane, fed by ONE graph-derived data source.
It is **not** the GP-E25 plan-register tree and must never be
presented as one; the plan-register tree is a separate data subject
that may at most reuse the presentation component.

**What will exist:**
- A read-only explorer rendering actual canonical idea/proposal
  identities and named lawful parent–child edges only: Ace's
  definition — growth parentage (proposal `parents`,
  `form/dell_matrix/nursery.py:402`) plus the registered graph's
  CONTAINS / DERIVED_FROM edges where supported.
- Confirmed vs pending provenance visibly distinguished (pending
  children shown as pending); unknown/unreadable/cross-owner links
  labeled **unavailable**, never invented.
- Deep-linking: views link to the same explorer with a selected-ID
  deep-link; selection/context synchronizes to Plane (see §7).
- No shadow tree database, no phantom edges, no write-back, no
  default confirmation or ownership bypass.

**Reads:** the one `SemanticGraph` (typed edges) and Nursery
proposal parentage records — both existing canonical sources. No
new store, no derived relationship inference ("mind-reading"
relationships are prohibited).

**Tree lineage truth table (contract the build must satisfy):**

| Case | Required rendering |
|---|---|
| Parent edge recorded in proposal `parents` and present in graph | node shown under that parent, confirmed/pending per proposal status |
| Edge present only as graph CONTAINS / DERIVED_FROM | shown, typed with its edge kind |
| Parent referenced but missing from the store | child shown with parent labeled unavailable; no phantom parent node |
| Cycle in parentage (A→B→A) | read fails closed for that subtree: cycle labeled, no infinite render, no write attempted |
| Duplicate ID in source records | refused/labeled as duplicate; never silently merged into one node |
| Cross-owner or unreadable relationship | labeled unavailable; no data from the other owner rendered |
| Stale generation (source revised since handoff) | labeled STALE per §7; selection never silently rebound |

**Test-first contract:**
- Failing-first REPL/browser assertions for each truth-table row,
  built from real program state (grow/confirm flows), not fixtures
  of the tree's own invention.
- Read-only proof: full traversal + deep-link open leaves canonical
  state hash unchanged; a pending child renders as pending and
  cannot be confirmed from the tree surface (no confirm control
  exists in the tree DOM).
- Disagreement probe: where authored `parents` and graph edges
  disagree, the rendering follows the precedence rule recorded in
  §9 item B (DECIDED, Director 7136755883): canonical parents
  govern ancestry, graph links render with their recorded type,
  the discrepancy is labeled, and both provenances are preserved.
  This probe is a full failing-first test, no longer SPEC-ONLY.

**Explicitly NOT authorized:** any TreeView implementation, any
labeling of a plan-register (GP-E25/H9) tree as the Idea TreeView,
any tree-side write, confirm, or ownership action.

## 4. SELECTION 3 — V09-PLAYGROUND: ISOLATED EXPERIMENTAL PREVIEW

**Decision (both dispositions agree):** an isolated experimental
preview for Dell chains and presentation experiments — **not** a
second production execution authority and **not** a second
confirm/execution door.

**What will exist:**
- User-initiated experiments against an explicitly identified clone
  or disposable sandbox program / a snapshot-deepcopy of selected
  owner state, reusing the canonical tokenizer/flow/seed grammar —
  never an alternate executor.
- Every run shows: input → parsed plan → predicted effects →
  before/after predicted state, output, and executed / skipped /
  refused provenance per step, under an unambiguous
  **"PREVIEW — not saved" / "SIMULATED / NO SAVE"** indicator.
- Timeout/step/resource caps; invalid input refused with a typed
  refusal, never a crash or partial silent run.
- Fail-closed when the clone/source snapshot cannot be verified.
- Promotion path: none inside the Playground. Any future move into
  the real program uses the existing authenticated canonical
  entry/confirmation path with a new explicit user action and new
  validation. No automatic export/merge of preview objects.
- Sound: S0 may be displayed only as a read-only descriptor; S1
  audio and S2 wiring remain separate approvals.

**Reads:** a verified snapshot/deepcopy of the one canonical store
for the SAME owner only. It never reads another owner's state and
never writes the canonical plane/Nursery/Exchange.

**Isolation threat model (contract surface):**

| Threat | Required defense |
|---|---|
| Preview mutates canonical state (direct or via shared references) | deepcopy/sandbox isolation; zero-canonical-write oracle (graph + store hashes identical before/after, including a discarded session) |
| Preview endpoint becomes a confirm/execute door | no confirmation or write path exists on any preview endpoint; route inventory test asserts the absence |
| Arbitrary code/import/file access via entered expressions | canonical grammar only; network, file, grant, and owner/memory side effects rejected with typed refusals |
| Cross-owner read through a crafted selection/ID | owner binding checked at snapshot creation; foreign-owner probe refused and labeled |
| Resource exhaustion (loops, the dormant `>>>` / `61[Join]` hang class) | timeout/step caps enforced; the known hang shapes are explicit negative tests that must terminate refused |
| Preview result mistaken for a real commit | persistent SIMULATED indicator in every output surface; one dry-run is never cited as proof of a future commit |

**Test-first contract:** the zero-mutation oracle; two-owner /
two-sandbox isolation cases; hang-shape negatives; typed-refusal
cases for network/file/grant-shaped inputs; snapshot-unverifiable
fail-closed case.

**Explicitly NOT authorized:** any Playground build, any production
state modification path (that would need a separate Ace/Director
authorized proposal with another gate), any S1/S2 audio work.

## 6. SELECTION 5 — V09-FRESHNESS: ONE SHARED FRESHNESS/CONTEXT
MECHANISM, NO SHARED DATA AUTHORITY

**Decision (both dispositions agree):** ONE shared snapshot/
revalidation infrastructure for V-08 view handoffs and GP-E25 Muse
Space evidence — but TWO separate acceptance scopes and credits:
V-08 presentation acceptance and GP-E25 snapshot-credit gates are
independently tested and ruled. Shared mechanism, **no** shared
data authority.

**What will exist:**
- One canonical handoff context shape carried across views:
  (owner, canonical idea/proposal ID, source generation/revision,
  read-only view, optional selection). Context may travel via
  URL/deep-link for nonsecret IDs only — never grant tokens or
  secrets in links.
- At each route/refresh, canonical revision and ownership are
  checked; the surface presents **STALE / UNKNOWN / OFFLINE**
  distinctly. If freshness is unresolved, any authority-changing
  action is blocked rather than silently proceeding on current
  state.
- Candidate primitives are the existing snapshot library's
  `revalidate()` / `offline_status()` (`muse_space_snapshot.py`) —
  which today have **no production caller** (research §1.6, C1
  audit §1) — adopted only after their current callers and pin
  behavior are verified. `muse_space_views.main()` takes no
  `--pin` today; the plan does not imply one exists.
- No forged last-updated time, no guessed totals; a client cache is
  never called a verified source.
- Both client and server display counts truthfully (Nursery
  shown/total; Plane edges displayed/available) — the core.js 400
  vs server 480 divergence is the standing example of why an
  upstream count alone never proves surface coverage.

**Reads:** canonical revision/ownership from the one program state
(V-08 side) and the one snapshot reducer (GP-E25 side) — each view
reads its own subject through the shared mechanism; one view never
mutates the other's plan files or state.

**Test-first contract:**
- 5×5 navigation persistence matrix (§7) executed as tests.
- Adverse probes: stale-generation handoff (selection from an older
  revision arrives → labeled STALE, not silently rebound);
  second-owner probe (context carrying another owner's ID →
  refused/labeled, no foreign data rendered); deleted-selection
  probe (selected idea removed between views → labeled, no
  substitute silently selected); reload and back/forward cases;
  keyboard-only completion of the matrix.
- Freshness labeling: STALE / UNKNOWN / OFFLINE each produced by a
  real induced condition and asserted on the surface.

**Explicitly NOT authorized:** wiring `revalidate()`/
`offline_status()` into production consumers (that is GP-E25 C1's
separately gated build — its authorization remains an owed ask and
V-09 does not waive it), any `--pin` claim, any cross-subject
mutation between V-08 pages and GP-E25 plan files.

- **A. Counts on new pages — DECIDED.** Divergence: 7095076955
  states "NO product page build" without exception language;
  7095187541 additionally authorizes the two bounded truthfulness
  repairs (executed as PR #521). **Ruling:** the #521 release

- **B. TreeView edge-source precedence — DECIDED.** Divergence:
  7095076955 sources the tree from proposal lineage AND graph
  CONTAINS/DERIVED_FROM "when supported"; 7095187541 requires the
  read contract to reject cycles, missing parents, and duplicate
  IDs; neither stated which source governs on disagreement.
  **Ruling:** same-owner canonical parents govern ancestry —
  proposal parents while the proposal is pending, accepted unit
  lineage after placement. Independently sourced graph links are
  shown with their recorded relationship type; they do not merge
  into ancestry. If sources disagree, the discrepancy is labeled

  `parents` and graph edges disagree; the rendering must follow
  canonical-parent ancestry, show the graph link typed with its
  relationship kind, display the discrepancy label, and keep both
  provenance records inspectable. (ii) Pending/placed transition:
  proposal parents govern while pending; after placement the
  accepted unit lineage governs — asserted across a real confirm
  flow. (iii) Unresolved-branch cases: missing parent, cycle, and
  duplicate ID each render a visible unresolved branch (the cycle
  case terminates rendering of that branch; no node is dropped
  and no IDs are silently merged) — these extend the §3 truth
  table, whose per-case renderings stand where they do not
  conflict with this ruling. (iv) Provenance: every rendered edge
  carries its source class (proposal-parent / accepted-lineage /
  graph-typed); the Keeper checks provenance at the final plan
  head.
- **C. Playground entry shape — DECIDED.** Divergence: 7095076955
  frames entry as user-initiated test seeds/Dells on a
  clone/sandbox program; 7095187541 frames entry as entered
  Mandell/Dell expressions simulated against a
  snapshot/deepcopy, with grammar-level negatives (including the
  `>>>` / `61[Join]` hang class). **Ruling:** one explicit
  expression-preview action is the entry shape. A selected
  admissible seed may prefill that same expression and supply
  read-only context. Only the user's explicit preview action runs
  the expression, and it runs against the isolated copy. The
  existing grammar is preserved, and SIMULATED is shown. The §4
  threat model stands. **Test specifications implied:**
  (i) no-run-on-select: selecting or prefilling a seed executes
  nothing — zero canonical and zero sandbox mutation until the
  explicit preview action. (ii) explicit-action-only: navigation,
  reload, and context changes never auto-run a prefilled
  expression. (iii) read-only isolation: the context a selected
  seed supplies is read-only to the preview run, and the run
  executes only against the isolated copy — the §4
  zero-canonical-write oracle stands unchanged. (iv) grammar
  preservation: expressions are accepted and refused exactly per
  the canonical grammar, including the §4 hang-shape negatives.
  (v) the SIMULATED indicator is present on the prefill surface
  and on every output surface.
- **D. Dells page content depth — DECIDED.** Divergence: the
  typed-signature / English-route / support-state requirement

  signature, English route, support state, and available proof.

  7095187541's proof links: the proof shown is the available

- **E. Mobile navigation mechanism — DECIDED.** Divergence:

- **F. Priority constraint asymmetry — DECIDED.** Divergence:
